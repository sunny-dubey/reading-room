# reading-room

**The Reading Room**: a site for *understanding* (not news) across four tracks: Distributed Systems & Databases, Backend/APIs/Payments, AI Engineering & Agents, ML & LLM Foundations, plus Postmortems. A small `/pulse/` page holds the week's headlines. Sunny's notebook (notes + saved links, written as files) is displayed read-only. Astro 5 static site, GitHub Pages, published on demand: no cron, a push to main (or a manual workflow run) builds and deploys a new edition. Today's deep read: up to 5 candidates rendered; the client shows the first not read and not shown on an earlier day (localStorage `plan:deep-shown`).

- Sources: `src/content/feeds.yaml`. Tracks: `CATEGORIES` in `src/lib/feeds.ts`. Ranking and Today page selection: `src/lib/reading.ts`.
- **Build-time article analysis, no AI model, no summaries:** `src/lib/summarize.ts` uses feed full-text or fetches the page (cached in `.cache/articles`, 30 days), then extracts concepts (VOCAB list), reading time, depth and a 1-5 `worth` score used for ranking. Deep reads = worth ≥ 3.5.
- The Canon (foundational reads, in order): `src/content/canon.yaml`. Progress lives in the browser (localStorage `canon:done`). Long works (books, courses, long videos) have `parts` (chapters or sittings); Today and the Canon page point at the next unfinished chapter, tracked as `<id>/<n>` in the same set (`src/lib/canon-parts-client.ts`), and finishing every chapter finishes the work.
- **Roadmap** (`src/content/roadmap.yaml`, page `/roadmap/`): Sunny's 25-area system design roadmap + AI engineering, ML foundations, payments, mathematics (29 areas, ~470 topics). `src/lib/embed.ts` runs a local embedding model (all-MiniLM-L6-v2 via @huggingface/transformers; cached in `.cache/models`, vectors in `.cache/embeddings.json`) at build time. `src/lib/roadmap.ts` matches each article to its closest topic (restricted by source track, see `ALLOWED`), giving cards a "Why read: you'll get better at <topic>" line and a rank boost for topics not yet covered by notes/saved links. If the model can't load, ranking falls back to the rules.
- **Overrides** (`src/content/overrides.yaml`): pin a roadmap topic for an article URL, or `none`.
- **Ranking:** `rank = worth×2 + freshness + topic boost + source weight`; freshness = 2.5 halving every 4 days (`freshness()` in reading.ts). Today has a "Fresh this week" block (worth ≥ 3, last 3 days, 7 if quiet) right after the plan; cards under 48h old get a "New" badge (client-side) (`weight` per feed in feeds.yaml; roundup/newsletter titles lose worth in summarize.ts).
- **Progress** is read-only on the site: Canon/Roadmap/plan ticks live in the browser (`src/lib/progress-client.ts`). Ids listed in `src/content/progress.yaml` (edit by hand) are merged in on every device and used by build-time ranking.
- **The site is read-only:** no in-site editor, saving, syncing or Explain-it-back. Notes and saved links are added as files (`npm run new`, `/til`, or editing `src/content/`).
- **Reading history** (`src/lib/history-client.ts`): opened pieces + timestamps in localStorage (`reading:history`); drives read dimming and spaced revisits (≈1 week / ≈1 month later) on Today.
- **Weekly design practice** (`src/content/practice.yaml`): one "Design a …" prompt per week on Today, with curated topics, Canon reads and a hard question; prompts not listed fall back to embedding matches. "Read first" never lists a whole book or course (book/course over 120 min is dropped with a build warning); it adds the best recent deep article (topic match ≥ 0.5) for the exercise topics when there is one.
- **Sources** (`src/pages/sources.astro`, in the sections bar): every feed grouped by track with posts, deep reads, latest post, best current read, ranking nudge and health.
- **Today extras** (`src/lib/today.ts` build-time picks, `src/lib/reading-stats-client.ts` in the browser): Question of the day (`src/content/questions.yaml`, rotates by IST date, hint + linked reads), time modes on the plan (15 min / 1 hour / weekend, remembered per day; steps carry `data-modes`/`data-min`, numbers via CSS counters), "Builds on a classic" (closest Canon read per article, `classic` in roadmap.ts, sim ≥ 0.5), Your reading (streak + 18-week grid from reading history and plan ticks), Rabbit hole of the day (topic with a fresh read + Canon, 3 steps easy → deep; client skips learned/already-shown topics), Two takes (two recent posts on one technical topic from different sources), Explainer of the day (`src/content/explainers.yaml`), Your week (Sunday/Monday recap; `?week` forces it).
- **Design:** Today is a newspaper front page (masthead with issue No. counted from 2026-11-17, ears, dateline; lead story = the picked deep read with a generative cover; sidebar = plan, question, your reading; bands with double rules). Track pages (`[section].astro`) are newspaper sections: section masthead, lead + two seconds with covers, more deep reads in covered columns, lighter reads as briefs, Canon + sources in a sticky sidebar. Other pages use `ReadingMast compact`, styled as a small masthead. `Story.astro` = newspaper story card (LearnCard is gone), `Cover.astro` = deterministic generative SVG per title and track. Editions: `html[data-ed]` (set in Base.astro from the reader's clock) re-tints the paper site-wide in light and dark. Motion (all behind prefers-reduced-motion): cross-page view transitions, `.reveal` sections fade up (observer in Base.astro), plan tick pop, "Done for today" stamp, streak flame, count-up stats, flash on Canon done.
- **Topic map** (Roadmap): 2D UMAP layout of topic embeddings (`umap-js`, seeded, cached in `.cache/topic-map.json`); dots by track, size by reads, learned topics glow; legend highlights a track; click opens the topic.
- **Outage map** (`/outages/`, panel on Today, "Outages" in the top nav): `src/lib/outages.ts` reads the status pages in `src/content/status-pages.yaml` (Statuspage atom incl. local time zones, incident.io atom, Google Cloud feed, AWS RSS), skips planned maintenance, rebuilds each incident's timeline (time to identify / mitigate / resolve), finds places with `src/lib/places.ts` (cloud region codes, Azure names, DC/airport codes, cities; broad areas are flagged approx.; nothing found = "global or not stated", never guessed), and matches investigation reports (provider postmortem status, GCP incident reports, monthly availability reports for the incident's month, or a same-provider post within 14 days sharing ≥5 meaningful words). Dotted map from `world-atlas` land via `src/lib/worldmap.ts` (cached in `.cache/world-dots-*.txt`). `IncidentReport.astro` renders the report; the investigation of the week prefers incidents with a report, a location and major impact.
- **Puzzle page** (band on Today right after the front; full page `/puzzles/`; "Puzzles" in the top nav): `src/lib/puzzles.ts`. Daily puzzle from `src/content/puzzles.yaml` (types bug/estimate/scenario/interleave/complexity, rotated round-robin by IST date; every answer is verified: bug snippets were run, interleavings enumerated by script, estimates show arithmetic in `proof`). "Numbers you should know" from `src/content/numbers.yaml` (derived or sourced; spaced repetition in localStorage `numbers:deck`, missed cards return in 2 days, known ones in 21). Incident drill: a real resolved incident from the outage pipeline with ≥4 updates, revealed one update at a time after you write a hypothesis (`drill:<id>`); the "first things to check" list is generic, rule-based. Results in `puzzles:results`. Client: `src/lib/puzzle-client.ts`. When adding puzzles, verify them the same way and add a `proof`.
- **The briefing** (`/briefing/`, five boxes on Today after Fresh, "Briefing" in the top nav; `src/lib/briefing.ts`): Release radar + Obituaries from endoflife.date for the products in `src/content/stack.yaml` (one row per project, newest line); CVE watch from CISA's Known Exploited Vulnerabilities JSON (last 21 days, `watch` words mark "your stack"; ransomware only when CISA says "Known"); Paper drop from arXiv RSS (8 cs.* categories, new submissions only, kept 7 days in `.cache/arxiv.json` for weekends, matched to Roadmap topics via `roadmap.topicVec`, ≤3 per category); Classifieds from the latest HN "Who is hiring?" (Algolia API; first paragraph = header; scored for backend/infra/distributed/payments/AI; "Open to India" = remote worldwide or India, region-limited remote excluded). Internet weather (`internetWeather()` in outages.ts) is the masthead's left ear.
- **Search** covers roadmap topics, Canon, articles, notes and saved links (`src/pages/search-index.json.ts`).
- **Today** (`src/pages/index.astro`): Today's plan (deep read with its Why read → next Canon item, rotating tracks daily → revisit from notes or reading history, else reflect), this week's design practice, Canon next-ups, picks, postmortem, revisit.
- `npm run check:links` checks Canon URLs (runs after each deploy, non-blocking).
- Tracks: systems, backend (shown as "Scalability & Architecture" at /architecture/), ai-eng, ml, security (roadmap area 32, cybersecurity engineer roadmap; lower match bar like math), math, postmortems (+ side pages pulse, startups).

## Content (all in `src/content/`, schemas in `src/content.config.ts`)

| What | Location | Frontmatter |
|---|---|---|
| Notebook notes | `notes/YYYY-MM-DD-slug.md` → `/notebook/<id>/` | `title`, `date`, `tags`, optional `source` (URL), `draft` |
| Saved links | `library.yaml` (list) → `/library/` | `id`, `title`, `url`, `author`, `kind`, `why`, `added`, `tags` |
| Canon | `canon.yaml` | see file header |
| Sources | `feeds.yaml` | see file header |

- The notebook has one kind of entry: a note (what Sunny understood, in his own words). No log/writing split.
- Tags are lowercase and kebab-case. Reuse existing tags before inventing new ones (`grep -rh "^tags:" src/content/notes`).
- `draft: true` shows in `npm run dev` and is hidden in production builds.

- Site is served under `/reading-room/` (GitHub Pages project site). Wrap every internal link in `u()` from `src/lib/url.ts`, never a bare `/path`.


## Commands

- `npm run dev`: local preview at http://localhost:4321
- `npm run build`: production build into `dist/`
- `npm run new "Title" [tags]`: scaffold a note
- `npm run check:links`: verify Canon links
